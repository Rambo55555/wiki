    1. Early-Bird Decoding：学习何时、以多大块提前提交 token

    题名： Early-Bird Decoding: Accelerating Diffusion LLMs with Learnable Block Sizes and Parallel Sampling
    作者： Lixuan Wei、Wei Zhou、Jianwen Wu、Yipeng Shen、Meiling Wang、Haoran You
    首发 / 更新 / 已核验版本： v1 于 2026-09-15 00:12:37 UTC 提交；截至本期仍为 v1。
    发表状态： arXiv 预印本；版本页未声明会议录用或正式发表。
    原文： 版本页 · HTML 全文 · PDF

    • 研究问题（论文事实）： 置信度阈值解码会反复重掩码“预测已正确但尚未达到阈值”的 token，固定块又忽略不同位置的难度差异；作者希望在不改动基模型权重的情况下更早提交这些 token。
    • 核心方法（论文事实）： EB-Decode 包含两个小型路由器。Learnable Block Sizer 根据熵、top-token 语义表示和位置特征，把低不确定 token 组成可变、可非连续的块；Position-aware Parallel Sampler 从“生成后回放”轨迹学习中间 top-1 是否会与最终基模型输出一致，并用加权二元交叉熵降低误提交。论文报告两模块约 0.6M 与 0.03M 参数；前者使用 92K 数学提示训练，后者用 10K AQUA-RAT 提示生成轨迹。
    • 实验与比较条件（论文事实）： 在 LLaDA-8B-Instruct、Dream-v0-Instruct-7B 与 LLaDA-1.5 上评测 GSM8K、MATH500、HumanEval、MBPP；主表生成长度 512、block 32、阈值 0.9、batch 1，并比较 vanilla、Fast-dLLM、AdaBlock 与 Learn2PD。部分主表关闭 KV cache，另在 4×A100 上单列 cache 结果。
    • 关键实验（论文事实）： HumanEval 上 LLaDA 吞吐从 23.70 升至 83.69 tok/s，准确率 43.90% 降至 43.29%；Dream 从 11.33 升至 63.53 tok/s，准确率维持 54.88%。MBPP 上 Dream 报告 18.76× 吞吐提升；GSM8K 的 LLaDA-512 设置为 6.14×，准确率从 79.07% 降至 78.24%。启用双 cache 时，EB-Decode 为 78.43 tok/s，Fast-dLLM 为 56.92 tok/s，但对应准确率为 77.93% 与 78.70%；作者估算路由器占 6.21% 开销。
    • 局限（论文事实与研究判断）： 论文只覆盖长度 256/512 和 batch 1，没有 continuous batching；LBS 的位置嵌入依赖生成长度，不同基模型/词表需单独训练路由器。路由器主要在数学数据上训练，代码结果属于迁移。研究判断： 3.53–18.76× 的 headline 主要来自 batch 1 且部分无 cache 设置，不能直接外推为生产服务收益；误提交造成的小幅精度变化也应纳入质量—延迟前沿。
    • 代码与数据： 论文未给作者官方代码、路由器权重或轨迹数据入口；题名、arXiv ID 与作者定向 GitHub 检索未定位官方实现。这里仅表示“截至截止时未定位”，不等于代码不会发布。
    • 与本方向关系 / 研究判断： 直接涉及 dLLM 解码、重掩码、动态块和服务。待验证判断： 学习“最终不会改变”的 token 比单看当前置信度更接近真正的提交风险，但需要跨域校准与并发服务实验才能确认其通用性。

    2. Register Tokens：用四个连续寄存器跨块保存推理状态

    题名： Register Tokens for Bounded-State Reasoning in Diffusion Language Models
    作者： Albert Ge、Chandan Singh、Yufan Zhuang、Xiaodong Liu、Jianfeng Gao、Frederic Sala
    首发 / 更新 / 已核验版本： v1 于 2026-09-14 21:34:15 UTC 提交；因 arXiv 公告批次在上次截止后出现，本期按新公告收录；截至本期仍为 v1。
    发表状态： arXiv 预印本；版本页未声明会议录用或正式发表。
    原文与资源： 版本页 · HTML 全文 · PDF · 训练混合数据 · 模型集合

    • 研究问题（论文事实）： dLLM 的跨块推理通常保留此前生成文本。论文测试能否清空旧文本，只携带固定大小连续隐藏状态继续推理。
    • 核心方法（论文事实）： 在固定位置加入 4 个 register tokens。模型生成一个 chunk 后清空该 chunk，但保留寄存器隐藏状态和原提示，再生成下一 chunk。作者以 chunked SFT 训练，单块使用 4 次去噪 loss pass；对照包括携带最后 4 个离散 token、带重建损失的 4 个 memory tokens 与完整序列 SFT，并把 chunked diffu-GRPO 用到 Countdown 和 LongArithmetic。
    • 实验与比较条件（论文事实）： backbone 为 LLaDA-8B-Base 和 Dream-7B-Base，SFT 数据为 60K 条 OpenMathInstruct-2 与 OpenCodeInstruct 混合。数学使用 128-token chunk、最多 8 块，代码使用 64-token chunk、最多 16 块，总预算 1024；在 GSM8K、GSM-Hard、MATH500、Omni-MATH easy、HumanEval 与 MBPP 上零样本评测。
    • 关键实验（论文事实）： registers 在两个模型、六个任务的 12 个设置中均优于离散文本携带，并在 10/12 设置中优于两种固定大小携带基线，最大数学/代码增益分别为 8.5/19.5 个点。LLaDA 的 HumanEval 为 26.2%，对比完整 SFT 14.0%、离散携带 18.3%、memory tokens 12.8%；Dream 的 MBPP 为 40.9%，对应为 30.0%、21.4%、4.7%。完整序列 SFT 仍领先全部 8 个数学设置；registers 则领先 4 个代码设置。LongArithmetic probe 对最终答案与运行总和的线性相关分别为 0.85/0.84。
    • 局限（论文事实）： 方法不等价于保留完整上下文；在 1024-token 预算内，完整推理轨迹的数学准确率仍更高。论文未测峰值显存、超出上下文长度的外推，也未与可见历史的 blockwise decoder 做系统比较；slot 数并非信息容量严格匹配，部分比较只有一个 seed。
    • 代码与数据： 论文写明代码将发布到 lbertge/dllm-registers-reasoning，但截止时该地址返回 404，不能写成代码已开放。训练混合数据页面可访问并显示 60K rows；Hugging Face 集合中多个模型条目可访问，因此数据和检查点属于“实际可下载”，代码仍是“作者承诺”。
    • 与本方向关系 / 研究判断： 直接覆盖 dLLM 长程推理、代码生成、RL 与 Agent 状态。待验证判断： 固定连续状态可能是工具调用和分支推理的紧凑接口，但需对状态容量、可解释性和错误累积做受控实验，不能仅凭 probe 认定寄存器已学到因果推理状态。

    3. PrismDiff：在一个画布中并行生成多种目标语言

    题名： Efficient One-to-Many Translation with Joint Multi-Stream Diffusion
    作者： Yiwen Guan、Jacob Whitehill
    首发 / 更新 / 已核验版本： v1 于 2026-09-14 20:20:46 UTC 提交；因公告批次在上次截止后出现，本期按新公告收录；截至本期仍为 v1。
    发表状态： arXiv 预印本；版本页未声明会议录用或正式发表。
    原文： 版本页 · HTML 全文 · PDF

    • 研究问题（论文事实）： 一源多目标翻译用独立 AR 解码器时，延迟随序列和目标语言数增长。PrismDiff 试图让多个目标流在同一扩散画布中联合、并行去噪，并保持对未见源语言的迁移。
    • 核心方法（论文事实）： 冻结 LaBSE 隐状态经投影形成语言无关语义锚；所有带噪目标流与锚拼入同一 canvas。语言特定 attention mask 允许共享模型同时生成各流，又阻止目标流互相直接读取；每流重置位置编码。解码使用迭代 masked diffusion、重掩码和加速的 log-uniform schedule，最后以 CTC collapse 去除重复。
    • 实验与比较条件（论文事实）： Multi30K 做 En→{De, Fr}，Europarl 做 En→{Fr, Nl, Ro, Da}，两者都以西班牙语作为未见源语言；扩散模型约 230M 参数，AR 对照约 208–247M，另比较 556M TET。延迟在单张 L40S、batch 1 下测量；Multi30K/Europarl 分别使用最多 100/40 步。
    • 关键实验（论文事实）： Multi30K 监督设置中，25 步 PrismDiff 的平均 BLEU/COMET/延迟为 36.97/0.715/68.7 ms；¾/8 层 AR 对照分别为 35.48/0.710/76.0 ms、36.03/0.720/92.5 ms、37.25/0.720/148.3 ms。西语零样本下 PrismDiff 为 28.22 BLEU、0.670 COMET、69.3 ms，最佳 AR4 为 26.03/0.670/92.5 ms。Europarl 20 步 PrismDiff 的监督平均为 28.84 BLEU、0.785 COMET、112.7 ms；TET 为 26.64/0.630/12.1 ms，说明单步 NAR 延迟仍明显更低。联合训练相对独立训练在 30 步时约提高 1.5/1.4 BLEU（监督/零样本）。
    • 局限（论文事实与研究判断）： 监督质量并非统一胜过 AR，扩散也慢于单步 NAR；零样本效果强依赖 LaBSE，对 mBERT/XLM-R anchor 的实验出现显著退化。固定 40/80 token block 在 Europarl 有溢出；只报告单 GPU、batch 1，没有多请求吞吐。研究判断： “目标数增加时次线性扩展”仍需在更多语言数和相同质量约束下测墙钟，而不能仅从两组任务外推。
    • 代码与数据： 论文未给作者代码、模型或项目页；题名/作者定向 GitHub 检索未定位官方实现。Multi30K、Europarl 与 LaBSE 是外部公开资源，不等于本文训练产物已发布。
    • 与本方向关系 / 研究判断： 这是 dLLM 多流条件生成和应用服务的直接实例。待验证判断： 共享语义锚与流隔离可扩展到多候选代码补丁或多 Agent 分支，但跨流不通信是否浪费可共享约束仍需比较。

    4. DBTM v2：直接学习自治传输图，并把多次调用变成自纠错

    题名： Discrete Beckmann Transport Models for One-Step Language Modeling and Reasoning
    作者： Sophia Tang、Shiyi Wang
    首发 / 更新 / 已核验版本： v1 于 2026-09-14 17:19:47 UTC 提交，早于上次截止但被漏收；v2 于 2026-09-15 14:23:01 UTC 更新，位于本次增量窗口。当前核验版本为 v2。
    发表状态： arXiv 预印本；版本页未声明会议录用或正式发表。
    原文： 版本历史 · v1 HTML · v2 HTML · v2 PDF

    • 研究问题（论文事实）： 现有一步/少步语言 flow map 常需先训练教师流再蒸馏，质量受教师限制且管线昂贵。DBTM 希望直接从数据学习一个时间无关、可单步到达离散顶点的映射，并让额外 NFE 用于细化而不是 ODE 积分。
    • 核心方法（论文事实）： 作者在单纯形上定义自治速度场及传输图 T；T 满足守恒残差 b·∇T=0，并在顶点流形上满足 T(x)=x。训练联合使用传输/JVP 残差、semigroup、边界与 anchor 约束，不依赖教师流或时间条件。partial-context interpolant 支持 refinement-in-loop：先提出完整序列，提交高质量 token，重噪其余位置并重复。
    • 实验与比较条件（论文事实）： 在 LM1B 长度 128（约 140M）与 OpenWebText 长度 1024（约 170–177M）做无条件语言建模，比较 Duo/MDLM 配合 DCD 或 Di4C、CFM、FMLM/FMLM+、DFM；另在 Sudoku 与由 TinyGSM 程序构造的 GSM8K 上测试推理。主指标同时报告 generative perplexity 与 entropy，避免只优化单一 PPL。
    • 关键实验（论文事实）： LM1B 1 NFE 下 DBTM+refinement-in-loop 的 GenPPL/entropy 为 85.5/3.92，对比 FMLM 119.34/4.16、DFM-PSD 94.08/4.06。OpenWebText 1 NFE 为 65.2/4.95，4 NFE 的 DBTM 为 52.⅖.26。Sudoku 在 16 NFE 的 easy/medium/hard 为 99.9%/99.4%/97.5%，FMLM+ 为 97.8%/92.6%/81.4%。GSM8K 则从 1 NFE 的 0.8% 升至 32 NFE 的 16.8%，仅略高于 FMLM+ 的 16.6%，远低于 512 NFE AR greedy 的 63.3%，说明复杂推理仍未由一步映射解决。
    • 局限（论文事实与研究判断）： 理论依赖单纯形、有限 hitting 与边界条件；经验规模和任务有限。OpenWebText 主模型使用 linear attention，而各基线的架构、训练步数和计算并非完全匹配；PPL–entropy 前沿会受 checkpoint 和采样旋钮影响。关键推理结果主要来自单一 checkpoint/argmax，未给置信区间，也没有端到端墙钟服务结果。研究判断： “1 NFE”是函数调用计数，不等于在相同硬件、batch 和吞吐约束下的一步系统延迟。
    • v2 实质变化（正文对照事实）： v2 新增明确的 Code Availability 小节与仓库链接，并把边界条件清楚写为 T(x)=x, x∈M₁，相应重排小节。论文声称代码“can be found”于 sophtang/DBTM，但截止时该地址返回 404，因此是“作者给出链接、实际不可访问”，不能写成代码已开放。
    • 代码与数据： 除上述 404 仓库外，论文没有可核验的作者模型或训练产物入口；LM1B、OpenWebText、Sudoku/TinyGSM 构造属于实验来源说明，不等于本文产物已下载验证。
    • 与本方向关系 / 研究判断： 直接连接离散/连续流、一步生成、训练目标与自纠错推理。待验证判断： 自治不动点为“多次调用只修错、不重新积分”提供了清晰目标，但需证明 refinement 的提交策略不会在长序列中锁死早期错误。

    综合判断与可执行研究问题

    本期形成三条相互衔接的线索：Early-Bird 学习局部提交时机，DBTM 把额外调用解释为不动点细化，Register Tokens 则把跨块历史压缩进固定状态；PrismDiff 展示多输出流可以共享语义锚和模型。以下均为待验证判断，不是创新性定论。

    1. 统一“可提交 token”学习： 在同一 LLaDA backbone 上把 Early-Bird 的最终一致标签与 DBTM 的 refinement-in-loop 结合，比较固定阈值、学习提交和可回滚提交；固定 KV cache、batch、长度与准确率，报告校准误差、锁死错误率和真实墙钟。
    2. 固定寄存器 × 自纠错映射： 让 DBTM 在跨块时只携带 4–16 个 register states，扫描状态容量和 chunk 数；同时与保留完整文本、离散 token 和常数状态 Mamba 比较显存、数学/代码准确率及错误累积。
    3. 多流状态共享： 把 PrismDiff 的共享语义锚用于多候选代码修复或多 Agent 分支，比较“流完全隔离”“共享寄存器”“允许受控跨流注意力”，判断并行分支能否共享约束而不发生模式串扰。

    精读优先： DBTM v2（理论目标、训练残差和推理细化可形成统一复现实验）与 Register Tokens（固定状态、长程推理和 Agent 接口的实验边界清晰）。
