### 1. DANTINOX：在同一工程框架中比较三种语言建模范式

**题名：** DANTINOX: A Unified Framework for Multi-Paradigm Language Modeling  
**作者：** Marco Simoni、Aleksandar Fontana、Giulio Rossolini、Andrea Saracino  
**首发 / 公告 / 已核验版本：** arXiv 版本史记录 v1 于 2026-07-11 08:46:11 UTC 提交；论文在 2026-09-17 UTC 的 [cs.CL new](https://arxiv.org/list/cs.CL/new) 中进入本次公告批次；截至本期为 v1。  
**发表状态：** arXiv 预印本；版本页未声明正式会议或期刊发表。  
**原文与资源：** [版本页](https://arxiv.org/abs/2609.17535v1) · [HTML 全文](https://arxiv.org/html/2609.17535v1) · [作者仓库](https://github.com/winstonsmith1897/DantinoX) · [PyPI 包](https://pypi.org/project/dantinox/)

- **研究问题（论文事实）：** AR、masked diffusion 和 continuous flow 语言模型常分散在不同代码栈，难以控制 tokenizer、骨干、初始化、数据和预算做直接比较。作者希望提供统一训练、推理和基准框架。
- **核心方法（论文事实）：** DANTINOX 以同一 JAX/Flax Transformer 骨干实现 AR、LLaDA 风格离散掩码扩散和 ELF 风格连续 flow matching，统一数据与训练管线；并把 MHA/GQA/MLA、MoE、流式推理和评测做成可组合配置。它首先是基础设施与受控比较框架，不是一个声称全面胜过现有模型的新预训练架构。
- **实验与比较条件（论文事实）：** 正确性验证在 WikiText-103 上将 12 层、hidden size 512、T5 32,128 词表的实现与独立 `dllm`、`xLM` 代码比较；扩散最终 loss 相差不超过 1%，AR 相差约 8%，作者把残差归因于 RMSNorm/权重绑定等默认差异。另训练 9 个范式×注意力组合的小模型（约 65–80M），使用三随机种子、100 个 128-token 无条件样本和 64-step 匹配推理预算，报告 MAUVE、GPT-2 PPL、Distinct-2、Rep-4 与条件 BLEU。
- **关键实验（论文事实）：** 在这组小规模、单语料实验中，flow 的流畅性指标最好、masked diffusion 的多样性更高，AR 的条件续写和重复控制更强；这些是同一小型设置下的相对结果。约 130M 模型在 A100-40GB、BF16、生成 256 token 的服务测试中，低 batch 下 diffusion 约 56 ms、AR 约 542 ms，作者报告约 7× 更低的每 token 能耗；AR 吞吐在 batch 约 32 后反超。
- **局限（论文事实与研究判断）：** 论文明确限制在小模型和 WikiText-103，未声称排序可扩展到更大模型或更广数据；flow 尚未暴露 prefix conditioning，效率也依赖去噪步数与质量折衷。**研究判断：** 该框架的价值更接近“消除工程混杂因素”，其范式优劣结论仍需在 1B+、相同训练 FLOPs 和下游任务上复核。
- **代码与数据：** 作者仓库实际可访问，含训练代码、文档、测试、配置和多次提交，采用 MIT 许可；PyPI 包可访问。论文数据使用 WikiText-103 等外部语料，本期未发现作者发布新的专用数据集或大模型检查点，也未运行代码。
- **与本方向关系 / 研究判断：** 直接覆盖离散扩散、连续流、训练目标、推理和公平评测。**待验证判断：** 如果框架能把训练 FLOPs、采样质量和服务负载统一为可复现协议，它可能成为检验“扩散语言模型何时优于 AR”的实用底座。

### 2. GroupKV：为块扩散长上下文做分层 KV 选择与预取

**题名：** GroupKV: Hierarchical KV Cache Management for Long-Context Diffusion LLM Inference  
**作者：** Jinhao Wang、Zhexin Hu、Kangjie Zhou、Xin Zhou、Fangfang Liu  
**首发 / 公告 / 已核验版本：** arXiv 版本史记录 v1 于 2026-07-30 16:19:56 UTC 提交；论文在 2026-09-17 UTC 的 [cs.OS new](https://arxiv.org/list/cs.OS/new) 中进入本次公告批次；截至本期为 v1。  
**发表状态：** arXiv 预印本；版本页未声明正式会议或期刊发表。  
**原文：** [版本页](https://arxiv.org/abs/2609.17573v1) · [HTML 全文](https://arxiv.org/html/2609.17573v1) · [PDF](https://arxiv.org/pdf/2609.17573v1)

- **研究问题（论文事实）：** 块扩散 LLM 在一个块内多次去噪，相邻步查询高度重叠；长上下文若把全部 KV 留在 GPU 会超显存，而逐 token 的 CPU 卸载选择又难以利用这种结构。GroupKV 试图在有限显存下保留准确率并扩大可服务上下文。
- **核心方法（论文事实）：** 方法先按连续 context group 做粗到细的稀疏 KV 选择，再利用跨层一致性预取下一层候选；并加入 staleness correction，修正跨去噪步复用选择带来的过期信息，配合 streaming prefill 控制峰值显存。选择单位与块扩散的局部上下文重叠对齐。
- **实验与比较条件（论文事实）：** 在 LLaDA 与 UltraLLaDA 两个相关 dLLM backbone 上评测 LongBench 7 个子任务、RULER 4K–32K 和 NIAH 4K–128K；比较完整注意力 UltraLLaDA/Fast-dLLM、FlexGen 风格全量卸载，以及为 dLLM 适配的 InfiniGen token 选择。硬件覆盖 A100-80GB 与 RTX 4090-24GB；关键准确率使用 20% KV budget。
- **关键实验（论文事实）：** LongBench 平均分为 LLaDA+GroupKV 32.73 对完整 LLaDA 33.10，UltraLLaDA+GroupKV 37.43 对完整 UltraLLaDA 36.61。RULER 16K/32K 为 70.22/62.81，完整 UltraLLaDA 为 68.46/62.70；NIAH 到 128K 平均 98.17%，128K 单点 95%。A100 上吞吐从 4K 的 10.64 tok/s 降至 128K 的 0.39 tok/s，相对 FlexGen 风格卸载为 2.0–3.7×、相对适配 InfiniGen 为 1.25–1.35×；摘要报告最高 3.73× 端到端加速和 48× 最大可服务上下文。
- **局限（论文事实与研究判断）：** 论文只覆盖两个相关 backbone 与两类硬件；部分系统基线是作者适配/复现而非官方 dLLM 版本，KV budget、主机—设备带宽和 batch 都会改变结论。正文没有独立 limitations 小节。**研究判断：** 128K 可服务不等于相同质量、并发和延迟 SLO 下可用，尤其需要复核预取命中率与 PCIe 饱和后的批处理行为。
- **代码与数据：** arXiv 正文未给作者官方仓库、模型或数据产物入口；按题名、方法名和作者定向检索未定位可归属作者的实现，故目前不能独立复现系统结果。LongBench、RULER 等是外部基准，不等于本文代码已开放。
- **与本方向关系 / 研究判断：** 直接覆盖 dLLM 长上下文、KV 缓存、显存卸载与服务。**待验证判断：** 块级稳定性可以成为系统稀疏性的额外信号，但需要与 token 置信度、内容相关性和真实请求调度联合评估。

### 3. ASRD v5：用稳定锚点做无额外前向的可撤销解码

**题名：** Follow the Latent Roadmap: Navigating Revocable Decoding for Diffusion LLMs with Anchor Tokens  
**作者：** Yizhen Yao、Qinglin Zhu、Runcong Zhao、Xiangxiang Dai、Yanzheng Xiang、Yulan He、Lin Gui  
**首发 / 更新 / 已核验版本：** v1 于 2026-06-15 15:23:47 UTC 提交；v5 于 2026-09-16 12:28:19 UTC 更新，位于本次增量窗口。当前核验版本为 v5。  
**发表状态：** arXiv 预印本。作者仓库 README 自述“Accepted to EMNLP 2026 (Main Conference)”，但本期未在正式论文集或可核验的官方会议条目独立确认，因此只记为作者自述录用。  
**原文与资源：** [版本历史](https://arxiv.org/abs/2606.16847) · [v5 HTML 全文](https://arxiv.org/html/2606.16847v5) · [v5 PDF](https://arxiv.org/pdf/2606.16847v5) · [作者仓库](https://github.com/preordinary/ASRD)

- **研究问题（论文事实）：** dLLM 的 token 预测可以在后续步骤被改写；仅凭当前置信度提交会锁死错误，而显式多次验证又增加前向计算。ASRD 尝试从已经稳定的 token 提取“潜在路线图”，在不增加模型调用的情况下发现仍不可靠的 token 并重掩码。
- **核心方法（论文事实）：** 连续 `k` 步保持不变的已提交 token 进入 FIFO Anchor Token Cache。Anchor-Guided Guidance（AGG）用熵加权的锚点质心混入 mask embedding；Anchor-Perturbed Verification（APV）沿与锚点方向正交的扰动测试待提交 token，若 top-1 预测翻转则撤销并重掩码。操作位于 embedding 层，兼容 FlashAttention，且不增加额外前向传播。
- **实验与比较条件（论文事实）：** 在 LLaDA-Instruct-8B、Dream-Instruct-7B 及其 base/RL 变体上评测 HumanEval、MBPP、GSM8K、MATH500，比较标准解码、WINO 和 Saber。生成长度主设为 512；实验使用 8×A100-80GB、temperature 0。不同模型与数据集使用调优后的阈值/超参数。
- **关键实验（论文事实）：** LLaDA 512 长度下，ASRD 的 HumanEval/MBPP/GSM8K/MATH500 为 48.8/39.4/81.1/38.8，对标准解码为 43.9/38.2/80.3/37.8，同时报告约 2.9–4.3× 加速。Dream 的 MATH500 为 45.0，对标准解码 38.6，并报告 5.4× 加速；MBPP 的最高加速为 7.2×。这些是作者在单一确定性运行和经调参设置下报告的点估计。
- **局限（论文事实与研究判断）：** 扰动测试只是一侧局部脆弱性检查；稳定 token 不保证语义正确，局部锚点也不提供全局正确性。论文每个配置只做一次确定性运行，阈值随模型/任务调优，且只覆盖四个 benchmark 与 7–8B backbone。**研究判断：** 加速数字需要在固定 cache、batch、真实服务调度及不针对测试集调阈值的条件下复核。
- **v5 实质变化（版本与资源事实）：** v5 正文新增可访问的代码入口；版本文件大小仅小幅变化，本期没有足够证据断言方法或实验表发生其他实质改动，因此只把“官方实现公开”记作已核验更新。
- **代码与数据：** [ASRD 仓库](https://github.com/preordinary/ASRD)实际可访问，采用 MIT 许可，含四组实验配置/脚本和评测目录，不是空仓库；其提交早于 v5，v5 是论文把入口公开出来。本期未运行代码，也未发现独立发布的训练数据或新权重。
- **与本方向关系 / 研究判断：** 直接涉及 dLLM 重掩码、可撤销提交、代码/数学推理与加速。**待验证判断：** 锚点稳定性比单步置信度提供了更接近轨迹一致性的信号，但还需测量“稳定却错误”的比例及其随长序列累积的风险。

## 综合判断与可执行研究问题

本期把范式级公平比较、长上下文系统优化和 token 级可撤销解码串到同一条质量—效率链路上。以下均为待验证判断，不是创新性定论。

1. **跨范式规模化对照：** 用 DANTINOX 把 AR、masked diffusion 与 continuous flow 扩到 1B+，固定 tokenizer、训练 FLOPs、数据顺序和采样质量，在 batch 1–128、短/长上下文下重测吞吐与能耗交叉点。
2. **锚点驱动的 KV 预算：** 将 ASRD 的稳定锚点/撤销信号加入 GroupKV 的 group 选择和预取，比较只用注意力相关性、只用稳定性以及二者联合时的准确率、预取命中率、PCIe 流量和锁死错误率。
3. **可复现长上下文服务：** 在更多 dLLM backbone 与 GPU/CPU 带宽组合上复现 GroupKV，统一 prefill、去噪步数、batch 和质量约束，并公开 OOM 边界与端到端延迟分解。

**精读优先：** [GroupKV](https://arxiv.org/html/2609.17573v1)（长上下文 dLLM 系统设计与基线公平性）和 [ASRD v5](https://arxiv.org/html/2606.16847v5)（可撤销提交机制、调参依赖及代码复现）。
