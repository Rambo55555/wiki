## 1. Graft：围绕任意位置锚点生成并保持全局一致

**题名：** In-Place Instruction Following in Diffusion Language Models  
**作者：** Zheng Nie、Zherui Li、Jiaming Zhang、Kun Wang、Zhenhong Zhou、Yufei Guo  
**首发 / 更新 / 已核验版本：** 2026-09-07 07:55:40 UTC；截至本期仍为 v1，无后续版本。  
**发表状态：** arXiv 预印本；未见作者在版本页声明正式录用。  
**原文：** [版本页](https://arxiv.org/abs/2609.07160v1) · [正文](https://arxiv.org/html/2609.07160v1) · [作者给出的匿名项目](https://anonymous.4open.science/r/Graft-36B5)

- **研究问题（论文事实）：** dLLM 可在输出中间固定任意锚点并双向补全，但现有指令跟随评测较少检查局部约束、边界衔接与全局语义能否同时成立。
- **核心方法（论文事实）：** 作者形式化 In-place Instruction Following（IIF），构建约 5K 条、覆盖字面/风格/篇章功能三层约束的 IIF-Bench；注意力偏置探针显示适度提高锚点权重有益、过强则伤害生成。Graft 先以约束感知 SFT 把锚点作为固定条件，再用 Graft-DPO 平衡局部执行、边界连贯和全局一致。
- **关键实验与比较条件（论文事实）：** 在 LLaDA-1.5、LLaDA-8B、Dream-7B、MMaDA 四个 dLLM 上，三次独立运行的平均 IIF 总分由 57.75 提至 73.10（+15.35）；字面和篇章功能约束分别提高 15.91、15.57 分。评测组合自动规则、LLM/奖励模型判断与人评，不能把该分数解释为通用能力准确率。
- **局限（论文事实）：** 主要是文本和有限场景；多语、多模态、交互编辑、超大模型及冲突锚点尚未验证。风格约束仍存在局部与全局权衡，基于 rubric 的自动评审可能有评估器偏差。
- **代码与数据：** 匿名项目链接可解析，但本次未能独立枚举或下载仓库文件，因此仅记为“作者提供链接”，不记作已验证可复现。
- **与本方向关系 / 研究判断：** 直接对应 dLLM 的任意位置填空和代码局部编辑。**待验证判断：** 若把字面锚点换成 AST 节点、测试契约或不可修改代码区，Graft 的训练目标可能改善编辑保留率；需用执行测试而非 LLM judge 验证。

## 2. DFlow：让被拒后缀的验证器表征流向下一轮草拟

**题名：** DFlow: Enabling Verifier Information Flow in Block Diffusion Speculative Decoding  
**作者：** Yaojie Zhang、Linfeng Zhang、Bin Cui、Xupeng Miao  
**首发 / 更新 / 已核验版本：** 2026-09-06 09:25:56 UTC；截至本期仍为 v1。  
**发表状态：** arXiv 预印本；版本页无正式发表声明。  
**原文：** [版本页](https://arxiv.org/abs/2609.06498v1) · [正文](https://arxiv.org/html/2609.06498v1)

- **研究问题（论文事实）：** 块投机解码通常只提交被接受前缀，目标模型已经为被拒后缀计算的隐藏状态被丢弃，下一轮草拟需重新构造未来表示。
- **核心方法（论文事实）：** DFlow 把被拒后缀的 verifier hidden states 经轻量中继模块送入下一草拟轮，并用 Multi-Round Self-Conditioned Training 学会跨轮利用这些信息；目标模型冻结，跨轮状态停止梯度，默认在初始预测后训练 2 个拒绝条件轮。
- **关键实验与比较条件（论文事实）：** 以 5 层、块长 16 的 DFlash drafter 配合 Qwen3-1.7B/4B/8B，在 GSM8K、MATH-500、HumanEval、MBPP、MT-Bench、Alpaca 上与 AR、EAGLE-3、DFlash 比较。贪心设置的六任务平均接受长度分别从 DFlash 的 3.56/3.71/3.66 提至 3.93/4.20/4.15；采样设置也提高。单节点 8×A800；SGLang 并发 1–32 的吞吐比较也优于 DFlash。中继报告增加 0.51 ms、约 1.2% 单轮开销。
- **局限（研究边界）：** 论文没有独立 limitations 节；结果集中于 Qwen3 家族、单一硬件环境和经训练的 drafter。接受长度与吞吐不是质量指标，且“无需额外目标前向”仍有中继和训练成本。
- **代码与数据：** 正文给出所用 ShareGPT 训练数据链接，但未定位作者官方实现或检查点，不能据论文结果称已可复现。
- **与本方向关系 / 研究判断：** 直接属于块扩散解码与服务。**待验证判断：** 对会重掩码或回退的编辑任务，应检查被拒状态是否携带过时约束，并报告错误传播而不只报告接受长度。

## 3. CONDOR：从逐位置边缘分布蒸馏到一次前向的联合块

**完整题名：** A Ticket from Marginals to Joints: Coupled-Noise Distillation for One-Step Block Generation in Diffusion Language Models  
**作者：** Lin Yao  
**首发 / 更新 / 已核验版本：** 2026-09-06 01:09:14 UTC；截至本期仍为 v1。  
**发表状态：** arXiv 预印本；版本页无正式发表声明。  
**原文：** [版本页](https://arxiv.org/abs/2609.06324v1) · [正文](https://arxiv.org/html/2609.06324v1)

- **研究问题（论文事实）：** dLLM 能否一次前向就提交一个连贯 token 块，同时让不同随机噪声选择不同联合模式，而不是各位置独立地产生不一致片段。
- **核心方法（论文事实）：** 先以随机掩码数和 winner-take-all 训练噪声条件 teacher；student 一步提出整块、保留部分 token，再让 teacher 在**同一高斯噪声场**下多步补齐其余位置形成蒸馏目标，并加入无噪声的真值 masked-LM 锚点。作者称该 coupled-noise 设计将噪声从粗粒度选择信号变成跨位置联合条件。
- **关键实验与比较条件（论文事实）：** 在 TinyStories 控制实验中生成 8-token 块；人评使用固定的 32 个提示、每个 16 个噪声场，共 512 块/模型。相同架构与提示下，最强一步 WTA 基线合法率 8.6%，keep-and-fill 蒸馏为 58.8%，加真值锚点为 64.8%，teacher-scored keep 为 73.4%；不同噪声仍产生 14–15 个不同字符串。该“合法率”是作者制定的片段规则，不是长文本质量或通用 benchmark 分数。
- **局限（论文事实与证据边界）：** 仅 TinyStories、小模型、8-token 块；32 个提示取评测窗口的前 32 个而非随机抽样，且由一位作者标注，没有标注者一致性或置信区间。长块、大模型及真实任务效果未验证。
- **代码与数据：** 正文称人评标签随代码发布（`judge/*.labels.json`），但 arXiv 页面未给仓库链接，本次亦未定位官方代码；因此记为“作者声称发布、实际入口未核验”。
- **与本方向关系 / 研究判断：** 直接研究单步块生成和蒸馏。**待验证判断：** 可把“块合法”替换为可执行代码片段的语法、变量绑定和测试约束，检验噪声能否控制联合模式而不牺牲正确率。

## 4. Uno：保留 AR 分布，用扩散适配器负责并行草拟

**题名：** Unlocking Lossless Speedups in LLMs via Discrete Diffusion  
**作者：** Subham Sekhar Sahoo 等（arXiv v1 列 17 位作者）  
**首发 / 更新 / 已核验版本：** 2026-09-03 15:48:43 UTC；截至本期仍为 v1。  
**发表状态：** arXiv 预印本；版本页无正式发表声明。  
**原文与资源：** [版本页](https://arxiv.org/abs/2609.04010v1) · [PDF](https://arxiv.org/pdf/2609.04010) · [项目页](https://s-sahoo.com/uno/) · [代码](https://github.com/ifm-ai/uno) · [权重集合](https://huggingface.co/collections/s-sahoo/uno)

- **研究问题（论文事实）：** 能否把扩散用于并行草拟，同时精确保留现有 AR 模型定义的目标分布，避免独立 draft model 和有损 dLLM 的质量变化。
- **核心方法（论文事实）：** AR 权重继续定义 next-token distribution；门控 LoRA 形式的 diffusion weights 通过单步块蒸馏与 total-variation 目标学习并行草拟。Ψ-Spec 的线性/树形采样器再用 AR 路径拒绝采样验证，因此论文中的“lossless”指目标分布保持，不等于零额外计算或逐次输出完全相同。
- **关键实验与比较条件（论文事实）：** 开源 UnoQwen 从 Qwen3-8B 初始化，冻结 AR 权重，训练约 0.35B 个 rank-128 适配器；OpenThoughts3-1.2M 上 14.7B token、32×H200 约 32 小时。1K 输入/8K 输出的单 H200 吞吐测试中，最大批量系统吞吐为 5733 tok/s，对 EAGLE-3 的 4944、DFlash 的 5351；batch=1 为 445/284/370 tok/s，附加参数为 0.35B/0.40B/1.05B。作者报告相对基础 Qwen 最高 2.5×（该开源设置）并在更广设置最高 3×。
- **局限（论文事实与比较边界）：** 每个生成步仍含草拟和验证两次前向；将二者合为一次的二次采样需要尚未实现的高效 kernel。专有 Uno 与 DiffusionGemma/Mercury 2 的部分比较涉及不同硬件和第三方结果。RL rollout 的“最高 40% 端到端训练加速”细节被明确留待后续版本，当前不能独立审计。
- **代码与数据：** `ifm-ai/uno` 为非空公开仓库，含训练、推理、评测及复现实例；项目页链接的 Hugging Face 集合包含可访问模型条目。这里只核验可下载性，未运行训练或复现论文数值。
- **与本方向关系 / 研究判断：** 直接连接离散扩散、蒸馏、服务和 RL rollout。**待验证判断：** 最值得做的是在相同硬件、序列长度、batch 和采样分布下与独立扩散 drafter 对比总拥有成本，而非只比较 tokens/step。

## 5. RAEC：利用早期且持续的拒绝信号做免训练安全解码

**题名：** Beyond Token Positions: Safety Alignment Across Denoising Steps in Diffusion Language Models  
**作者：** Guoli Wang、Haonan Shi、Tu Ouyang、An Wang  
**首发 / 更新 / 已核验版本：** 2026-08-31 23:50:31 UTC；截至本期仍为 v1。  
**发表状态：** 作者在 arXiv 备注“Accepted by EMNLP 2026”；本次未取得可独立确认的正式论文集条目，故不写作已正式发表。  
**原文与资源：** [版本页](https://arxiv.org/abs/2609.00495v1) · [正文](https://arxiv.org/html/2609.00495v1) · [作者仓库](https://github.com/Glresearch1/RAEC)

- **研究问题（论文事实）：** dLLM 的安全不仅与 token 在回答中的位置有关，也与其在何时去噪并被提交有关；拒绝信号可能早已出现，却在后续步骤被覆盖。
- **核心方法（论文事实）：** RAEC 在前 8 个去噪步和前 8 个回答位置监视拒绝/服从 token 概率质量；信号连续 3 步高于阈值、强于服从证据且进入 top-k 时，最多提前提交 2 个拒绝 token。方法只改变 commitment rule，不训练参数，也不增加目标模型查询。
- **关键实验与比较条件（论文事实）：** 在 LLaDA-8B-Instruct 与 Dream-v0-Instruct-7B 上，以 Llama-Guard-3-8B 评估 StrongREJECT、JailbreakBench、HarmBench 及 DIJA 变体，并以 GSM8K、AGNews 检查效用。LLaDA 上 DIJA-SR/JBB/HBB 的 ASR 分别从 8.63/8.00/40.50 降至 6.71/6.00/34.00，GSM8K/AGNews 从 54.66/82.30 变为 54.44/82.20；但普通 StrongREJECT 从 1.28 升至 1.60，故只可称“多数设置改善”。自适应 PAIR 上为 48%→36%，人评与另一安全 judge 的方向一致。
- **局限（论文事实）：** 主要基于 vanilla LLaDA/Dream，Dream 设置仍受 LLaDA 可用设置约束；未覆盖新架构或微调期间的安全动态。拒绝 token 早提交还可能引入过度拒答，两个通用效用集不足以排除更广副作用。
- **代码与数据：** 官方 GitHub 仓库可访问，但本次文件树只有 1 字节占位文件，没有可运行实现或数据，不能称已开源可复现。
- **与本方向关系 / 研究判断：** 直接揭示去噪时间轴上的安全面。**待验证判断：** 应在 harmless-but-sensitive、长回答和代码安全任务上画安全—效用 Pareto 曲线，并测试攻击者能否专门稀释早期拒绝质量。

## 6. CARVE：以反事实稳定性决定是否扩展 masked canvas

**题名：** CARVE: Verified Expansion for Variable-Length Generation in Diffusion Language Models  
**作者：** Wail Bouhedja、Amr Mohamed、Guokan Shang  
**首发 / 更新 / 已核验版本：** 2026-08-31 15:00:30 UTC；截至本期仍为 v1。  
**发表状态：** arXiv 备注“EMNLP 2026 Findings”；正式论文集条目本次未独立确认，按作者自述录用记录。  
**原文与资源：** [版本页](https://arxiv.org/abs/2608.30922v1) · [正文](https://arxiv.org/html/2608.30922v1) · [代码](https://github.com/wailji/CARVE)

- **研究问题（论文事实）：** masked dLLM 通常在解码前固定回答长度；过短会截断，过长会浪费计算并可能扰动去噪。动态插入 mask 又会改变既有未决位置的预测分布。
- **核心方法（论文事实）：** CARVE 从半长 canvas 起步，在高不确定区域提出固定 16 个 mask 的扩展分支；对齐原有未决位置，计算扩展前后分布的平均 Jensen–Shannon divergence，低于阈值才保留。再配合自适应 reveal 数量、EOS 裁剪和末次贪心补全；无需训练，适用于 full-canvas Dream 与 blockwise LLaDA。
- **关键实验与比较条件（论文事实）：** 在 Dream-v0-Instruct-7B、LLaDA-1.5、LLaDA-8B-Instruct 的 HumanEval/MBPP（pass@1）与 MATH-500/GSM8K（exact match）上，与各模型固定长度解码及 DAEDAL 比较。四任务平均相对固定长度提高 0.92/1.03/0.49 个百分点，但 12 个模型—任务组合仅 9 个提高，且 LLaDA-8B 上 DAEDAL 平均 53.42 高于 CARVE 53.20。作者报告部分设置 FLOPs 约减半；8×MI210 实测吞吐比从 0.93 到 3.10，说明不同任务并非都加速。
- **局限（论文事实）：** 扩展块固定为 16，未按样本长度需求自适应；JS 只比较原有未决位置，不包含新位置，也不保证逐位置保持、语义正确或安全。分支额外前向是否被 EOS 裁剪抵消取决于任务和响应长度。
- **代码与数据：** 官方仓库为非空公开实现，包含 Dream/LLaDA/LLaDA-1.5、四个 benchmark 的脚本和 `reproduce.sh`；未在本期实际运行复现。
- **与本方向关系 / 研究判断：** 直接解决动态长度。**待验证判断：** 对代码生成应按函数闭合、测试覆盖和 AST 稳定性自适应插入大小，比较真实墙钟与“只看 FLOPs”的排序是否一致。

## 7. DiffPDE：用重掩码和执行反馈做局部代码修复

**作者：** Wenxuan Guo、Yuyang Hong、Lubin Fan、Zhaojin Fu、Lin Chen、Kun Ding、Shiming Xiang

- **研究问题（论文事实）：** PDE solver 的运行错误常集中在少数代码段，AR 模型每轮全量重写造成冗余；dLLM 的双向填空能否只修坏掉的 span，并用多轮执行反馈训练。
- **核心方法（论文事实）：** 基于 Dream-Coder-7B，先从 traceback 行向上下自然边界定位错误块，只重掩码该 span 并在左右完整上下文中填空；SFT 后使用 Iterative Debugging GRPO（ID-GRPO），把错误签名严格缩减作为中间奖励，并混合构造填空任务与错误驱动任务。训练约 1K 轨迹、60 个 RL 更新，8×A800 合计约 350 GPU 小时。
- **关键实验与比较条件（论文事实）：** PDEBench 的 Advection、Burgers、Reaction–Diffusion、1D CNS、Darcy 五类任务；每类生成 32 个候选、最多 3 次修复，比较专家/神经 solver、多个大型 API 模型和 Qwen2.5-Coder-7B/Qwen3-8B。DiffPDE-7B 的五类 nRMSE 为 4.5e−3、9.7e−4、3.0e−2、1.8e−1、1.0；Darcy 的 Pass@32 仅 0.09。初始生成平均 53.17 秒，慢于同规模 AR；局部修复 0.60–0.99 秒，最坏三轮总成本均值 55.5 秒，对 Qwen2.5-Coder-7B 的 102.1、Qwen3-8B 的 119.3。相同 DiffPDE checkpoint 下局部填空对全量重生成约 86×/次，但这不是端到端 86×。
- **局限（论文事实）：** 只研究有 traceback 的局部 PDE 代码调试；初始失败中 5.4% 需全局结构修改、17.9% 为格式或无 solver，当前框架不能完整处理。更大扩散 backbone、全局跨区域编辑及更先进解码仍未验证；best-of-32 不能与单次成功率混用。
- **代码与数据：** 论文链接的 GitHub 仓库可访问，但截至本期只有一个 164 字节 README，没有实现、权重或训练数据；PDEBench 是外部公开数据集。不可将项目链接存在写成代码已发布。
- **与本方向关系 / 研究判断：** 直接覆盖代码编辑、重掩码、执行反馈与 RL。**待验证判断：** 在通用软件仓库中，先比较错误定位质量，再比较局部 dLLM 与 AR patch 模型；必须同时报告测试通过、非目标代码改动量和多文件全局修复失败率。

## 综合判断与可执行研究问题

本期补录把三个此前空缺的轴补齐：**任意位置约束（Graft）—动态长度（CARVE）—局部执行反馈修复（DiffPDE）**；同时 DFlow、CONDOR、Uno 分别代表跨轮表征复用、单步联合块和 AR 分布保持式扩散草拟。以下均是待验证判断，不是创新性定论。

1. **统一编辑控制器：** 在同一代码编辑基准中，把 Graft 的固定锚点、CARVE 的 canvas 扩展、DiffPDE 的 traceback 重掩码组合成“保留—扩展—修复”三类动作；报告测试通过率、编辑保留率、墙钟时间和额外前向数。
2. **草拟信息的价值与风险：** 在同一 Qwen3 目标模型、硬件和 batch 下比较 DFlow 的被拒表征、CONDOR 的共享噪声与 Uno 的分布保持验证，测接受长度之外的校准、错误相关性和总内存。
3. **安全提交时机：** 将 RAEC 的早期持续信号推广到代码安全策略，但加入过度拒答、良性敏感请求与自适应稀释攻击，画出安全—效用—延迟三维 Pareto 前沿。

**精读优先：** [Uno](https://arxiv.org/pdf/2609.04010)（方法和系统评测链条最完整）与 [DiffPDE](https://arxiv.org/html/2608.30532v1)（最直接连接重掩码、执行反馈和软件工程）。
